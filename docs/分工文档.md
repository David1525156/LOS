## 2. 分工原则

1. **按模块划分**：以 Sprint 1 的 3 个用户故事（US-01 图书列表、US-02 图书详情、US-03 新增图书）为粒度切分模块，各模块边界清晰、互不阻塞；
2. **前后端分离**：前端（Vue3+Vite）、后端（Spring Boot + MyBatis-Plus）各 3 人，通过 API 接口文档协作；
3. **一人一模块主责**：每个成员对所属模块的开发与自测负首要责任；
4. **代码评审**：合并代码前由项目负责人（孟函笑）组织交叉评审，确保质量与一致性。

## 4. 成员职责明细

### 4.1 孟函笑（项目负责人 / 需求与数据库设计）

- 编写《项目需求文档》，拆解 Sprint1 用户故事与验收标准；
- 设计数据库表结构（book、admin）并编写建库初始化脚本与《数据库设计文档》；
- 制定《API 接口文档》与《分工文档》，统一响应规范（code/message/data）；
- 组织每日进度同步、代码评审与集成测试，把控 Sprint1 交付节点。

### 4.2 韩大伟（后端：框架与认证）

- 搭建 Spring Boot 工程（pom.xml、application.yml、启动类），引入 MyBatis-Plus 并配置驼峰映射；
- 实现统一响应体 `Result`、全局异常处理器（校验异常 / 业务异常 / 500 兜底）；
- 实现管理员登录接口 `POST /api/auth/login` 与 Token 校验拦截器（保护新增接口，非 GET 写操作鉴权）；
- 编写登录与拦截器相关单元测试，配合邓寅卓完成登录前端联调。

### 4.3 王明凯（后端：图书查询 US-01 / US-02）

- 实现图书列表接口 `GET /api/books`（分页、每页 10 条、新书优先排序）；
- 实现图书详情接口 `GET /api/books/{id}`（含「图书不存在」业务异常处理）；
- 编写列表分页与详情相关单元测试，配合王煜哲完成前端联调。

### 4.4 李自谦（后端：图书新增 US-03）

- 实现新增图书接口 `POST /api/books`（书名/作者必填、库存非负等参数校验，@Validated）；
- 校验失败错误提示的友好返回（返回字段级错误信息，非法输入弹出提示）；
- 编写新增图书相关单元测试（正常新增、参数非法、无 Token 401 等），配合邓寅卓完成前端联调。

### 4.5 王煜哲（前端：图书浏览 US-01 / US-02）

- 搭建 Vue3 + Vite 前端工程，引入 Element Plus、Vue Router，封装 axios 请求与统一错误提示；
- 实现图书列表页（分页表格：书名、作者、库存；加载失败友好提示）；
- 实现图书详情页（书名、作者、简介、可借阅库存；点击列表条目跳转）；
- 对接王明凯的列表/详情接口，负责前端路由与全局布局。

### 4.6 邓寅卓（前端：管理员功能 US-03）

- 实现管理员登录页（调用登录接口，保存 Token）；
- 实现新增图书表单页（登录后可见可打开，提交新增；非法输入弹出错误提示）；
- 配置路由守卫（未登录访问新增页跳转登录）；
- 对接韩大伟的登录接口与李自谦的新增接口。

## 5. 协作机制

### 5.1 接口协作

- 以《API 接口文档》为唯一契约；后端先行交付接口，前端按契约开发；
- 接口变更须提前通知联调对方并同步更新文档。

### 5.2 Git 协作规范

- 仓库：GitHub（https://github.com/David1525156/LMS），分支：`main`；
- 各模块在 `feature/<模块名>` 分支开发，自测通过后合并到 `main`；
- 合并前需经过至少一名其他成员代码评审；提交信息遵循「动词 + 模块」格式。

### 5.3 测试与验收

- 后端成员对各自模块编写单元测试，保证 `mvn test` 全绿；
- 集成阶段由孟函笑统一执行端到端验收（对照 3 个用户故事的验收标准逐条验证）。
