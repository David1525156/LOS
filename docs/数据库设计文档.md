# 在线图书借阅系统 数据库设计文档

| 项目 | 内容 |
| --- | --- |
| 数据库名称 | `library` |
| 数据库版本 | MySQL 8.0 |
| 字符集 | utf8mb4 / utf8mb4_general_ci |
| 引擎 | InnoDB |
| 文档版本 | v1.0 |
| 当前迭代 | Sprint 1 |

---

## 1. 概述

本系统数据库 `library` 承载图书信息与管理员的持久化存储。Sprint 1 仅涉及图书浏览、详情与管理员新增图书，因此当前仅包含两张表：

| 表名 | 说明 | 归属模块 |
| --- | --- | --- |
| `book` | 图书信息表 | 图书浏览 / 新增（US-01/02/03） |
| `admin` | 管理员表 | 管理员登录（US-03） |

后续迭代（借书、还书、用户注册）将在第 5 节中规划新增表结构。

---

## 2. 设计规范

### 2.1 命名规范

| 约定 | 规则 | 示例 |
| --- | --- | --- |
| 数据库名 | 小写英文单词 | `library` |
| 表名 | 小写下划线 | `book`、`admin` |
| 字段名 | 小写下划线 | `create_time`、`description` |
| 主键 | 统一 `id`，BIGINT 自增 | `id` |
| 外键/索引 | `idx_字段名` | `idx_title` |

### 2.2 其他约定

- 主键使用 `BIGINT AUTO_INCREMENT`，避免使用业务字段作主键；
- 字符字段统一 `VARCHAR`，长度按业务上限 + 冗余设定；
- 所有表使用 `InnoDB` 引擎（支持事务与外键）；
- 字符集统一 `utf8mb4`，支持中文及 emoji；
- 字段注释（`COMMENT`）必填，保证可维护性；
- MyBatis-Plus 开启 `map-underscore-to-camel-case`，实体驼峰字段与数据库下划线字段自动映射。

## 3. 表关系

Sprint 1 两张表相互独立，无外键关联。

```
┌───────────────┐        ┌───────────────┐
│     book      │        │     admin     │
├───────────────┤        ├───────────────┤
│ id (PK)       │        │ id (PK)       │
│ title         │        │ username (UK) │
│ author        │        │ password      │
│ description   │        └───────────────┘
│ stock         │
│ create_time   │
└───────────────┘
```

> 说明：管理员与图书之间无归属关系，图书由管理员统一维护。

## 4. 表结构设计

### 4.1 图书表 `book`

**用途**：存储图书的基本信息与可借阅库存。

```sql
CREATE TABLE book (
    id          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
    title       VARCHAR(100) NOT NULL COMMENT '书名',
    author      VARCHAR(50)  NOT NULL COMMENT '作者',
    description VARCHAR(1000) DEFAULT NULL COMMENT '图书简介',
    stock       INT          NOT NULL DEFAULT 0 COMMENT '可借阅库存',
    create_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    PRIMARY KEY (id),
    KEY idx_title (title)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '图书表';
```

| 字段 | 类型 | 允许空 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| id | BIGINT | 否 | 自增 | 主键，图书 ID |
| title | VARCHAR(100) | 否 | - | 书名（非空，≤100 字符） |
| author | VARCHAR(50) | 否 | - | 作者（非空，≤50 字符） |
| description | VARCHAR(1000) | 是 | NULL | 图书简介（≤1000 字符） |
| stock | INT | 否 | 0 | 可借阅库存（≥0） |
| create_time | DATETIME | 否 | CURRENT_TIMESTAMP | 创建时间，用于列表按新书排序 |

**索引**：

| 索引名 | 类型 | 字段 | 用途 |
| --- | --- | --- | --- |
| PRIMARY | 主键 | id | 主键查询 / 详情查询 |
| idx_title | 普通索引 | title | 后续迭代按书名检索（Sprint 2 预留） |

**约束说明**：

- 库存非负约束由应用层校验（`@Min(0)`），Sprint 1 未加数据库 CHECK 约束（MySQL 8.0.16+ 已支持 CHECK）；
- 创建时间由数据库默认值维护，新增时无需显式赋值。

### 4.2 管理员表 `admin`

**用途**：存储管理员登录账号。

```sql
CREATE TABLE admin (
    id       BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
    username VARCHAR(50)  NOT NULL UNIQUE COMMENT '用户名',
    password VARCHAR(100) NOT NULL COMMENT '密码(Sprint1 演示用明文,后续可改 BCrypt)',
    PRIMARY KEY (id)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '管理员表';
```

| 字段 | 类型 | 允许空 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| id | BIGINT | 否 | 自增 | 主键，管理员 ID |
| username | VARCHAR(50) | 否 | - | 用户名，唯一 |
| password | VARCHAR(100) | 否 | - | 密码（Sprint 1 演示用明文） |

**索引**：

| 索引名 | 类型 | 字段 | 用途 |
| --- | --- | --- | --- |
| PRIMARY | 主键 | id | 主键查询 |
| username | 唯一索引 | username | 登录时按用户名精确查询，保证唯一 |

## 5. 后续迭代表规划（Sprint 2+）

随借书、还书、用户注册功能上线，计划新增以下表（当前未创建）：

| 表名 | 用途 | 关键字段（规划） |
| --- | --- | --- |
| `user` | 读者用户表 | id, username, password(BCrypt), nickname, create_time |
| `borrow_record` | 借阅记录表 | id, user_id(FK), book_id(FK), borrow_time, due_time, return_time, status |

**调整建议**：

- `book.stock` 在借书/还书时进行扣减与恢复（事务保证一致性）；
- `admin` 表未来可与 `user` 表合并为统一账号体系（增加角色字段 `role`）。

## 6. 初始化与种子数据

初始化脚本位于 `db/init.sql`，包含：

1. 建库：`CREATE DATABASE IF NOT EXISTS library ... CHARACTER SET utf8mb4`;
2. 建表：`book`、`admin`；
3. 预置管理员：`INSERT INTO admin (username, password) VALUES ('admin', '123456')`;
4. 预置 25 本图书种子数据（覆盖中外经典书目，库存 1~9 不等），用于分页功能验证。

执行方式：

```bash
mysql -uroot -p < db/init.sql
```

验证：

```sql
SELECT COUNT(*) FROM library.book;   -- 预期 25
SELECT username FROM library.admin;  -- 预期 admin
```

## 7. 设计决策与说明

| 决策 | 说明 |
| --- | --- |
| 为什么用自增主键 | 图书 ID 无业务含义，自增主键查询效率高、避免业务耦合 |
| 为什么库存不建 CHECK 约束 | Sprint 1 由应用层校验足够；避免初始化脚本兼容性负担 |
| 为什么密码存明文 | 仅 Sprint 1 演示用，文档与代码均已注释提示，后续迭代升级 BCrypt |
| 为什么书名建普通索引 | 为 Sprint 2 按书名检索预留，Sprint 1 列表仅按创建时间排序 |
| 为什么用 utf8mb4 | 完整支持中文与特殊字符，杜绝乱码 |
